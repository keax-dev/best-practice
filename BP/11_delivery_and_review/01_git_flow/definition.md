# Git Flow

## ¿Qué es?

Es asignar un propósito a cada tipo de rama y acordar cómo pasan los cambios entre ellas.

## ¿Cómo funciona y para qué sirve?

El flujo interno distingue feature, develop, release, hotfix y master. Las protecciones y ambientes se configuran en la plataforma de entrega.

## Qué muestra el ejemplo

Compara el caso problemático de `before.md` con la respuesta propuesta en `after.md`.

Tecnología: **Git y proceso de entrega**.

## Qué pide la organización

La guía interna pide aplicar esta práctica según el tipo de componente. Los valores del ejemplo son didácticos y no representan parámetros productivos aprobados.

## Límites y aclaraciones

Git Flow es la estrategia descrita por la organización, no una obligación para todos los repositorios. No se cambian ramas ni se ejecutan comandos Git desde el ejemplo.
